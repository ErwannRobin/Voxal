## iOS / Capacitor

- `navigator.clipboard.writeText` fails silently in WKWebView → use `fallbackCopy()` (textarea + `execCommand('copy')`).
- `navigator.share()`: iOS rejects `url:` for non-http(s) schemes (`voxal://`) → pass the deep link in `text:`. For http invite links share with `url` only (text+url duplicates the link in some targets). Inside an iframe it can throw `NotAllowedError` → always keep a copy fallback. The "Unable to hide query parameters" log is harmless.
- **Voxal Connect (auth) on web returns over https, never `voxal://`** (a custom scheme dead-ends in a browser). Web sends `responseMode=redirect` + `redirect_uri=<origin>/auth/callback`; native keeps `responseMode=deep-link` (server default, so old native builds still work). Server repo: `ErwannRobin/voxal-presence`.
  - Server must validate `redirect_uri` against an **origin allowlist**, never a string prefix (`https://ptt.voxal.app.evil.com` passes `startsWith`), and must **error**, not fall back to the deep link.
  - Popup + `postMessage` could never work: `vercel.json` sets COOP `same-origin` (needed for SharedArrayBuffer/RNNoise), which severs `window.opener`. Same-tab redirect avoids it; so Connect is blocked while `inRoom`.
  - Strip the token from the URL immediately (`history.replaceState`), also on the rejected-state path.
  - `/auth/callback` must be a **real file** (`src/auth/callback.html`, does `location.replace('/' + location.search)`), not a `vercel.json` rewrite: with `cleanUrls`, a rewrite to `/index.html` 404s in prod. A file also works on any static host.
- `navigator.onLine` says nothing about relay availability. The relay badge derives from `_lastIceResolution` (set by `noteIceResolution()` at every return of `fetchIceServers()`), **not** `METERED_STATUS_STORE_KEY` (only written by org path / Test TURN, persisted, goes stale).
- **PTChannelManager** (PushToTalk) owns the AVAudioSession exclusively: never `setActive(true)` at launch, only in `didActivate`/`didDeactivate`; never `setCategory` in `didActivate` (breaks WebRTC audio) — just `setActive(true)`. `channelManager(...)` init is async: `join()` must await a continuation (5 s timeout) or the Dynamic Island button does nothing. Complete the Capacitor `call` on the main thread (`await MainActor.run { call.resolve() }`).
- **WKWebView JS is suspended in background** even with audio/voip/PTT modes. Keep a Web Audio graph running while in a room (`Oscillator → Gain(0) → destination`) so iOS keeps the WebContent process alive. Route the mic through a `GainNode` (not `track.enabled`) so Swift can gate PTT without JS. The AudioContext may be suspended: in `didBeginTransmittingFrom` do `audioCtx.resume().then(() => gain.value = 1)`.
- **Universal Links cold launch**: iOS delivers the activity via `scene(_:willConnectTo:options:)` (`connectionOptions.userActivities`), NOT `scene(_:continue:)` (warm launch only). Handle both. `voxal://` is in `Info.plist` `CFBundleURLSchemes`; cold-launch deep links come via `App.getLaunchUrl()`, runtime ones via `appUrlOpen`.
- **PushToTalk framework facts** (iOS 16+, verified against SDK headers): PTT button = `didBeginTransmittingFrom`/`didEndTransmittingFrom` (NOT `didActivate`/`didDeactivate`, which are audio-session lifecycle). Swift renames the header's `didActivateAudioSession:` to `channelManager(_:didActivate:)` — trust the compiler. All delegate methods except `failedToJoin/Leave/Begin/Stop` are **required**; `incomingPushResult` must return a non-nil `PTPushResult` (`.leaveChannel` is a safe no-op). Ignore `source == .developerRequest` in transmit callbacks (your own echo). Use `setTransmissionMode(.fullDuplex, …)` in `didJoinChannel` (default half-duplex blocks receive). The plugin class must still load on the iOS 15 target: store the manager as `Any?` behind an `@available(iOS 16.0, *)` accessor. The Simulator cannot exercise PTT (compile check only: `xcodebuild -sdk iphonesimulator … CODE_SIGNING_ALLOWED=NO`).
- New `.swift` files under `ios/App/App/` must be registered by hand in `project.pbxproj` (PBXBuildFile/FileReference/Group/SourcesBuildPhase) or they are never compiled and `Capacitor.Plugins.X` is `undefined`.
- **RNNoise crackle was a worklet phase bug on every device, not a mobile headroom problem.** RNNoise emits 480-sample frames, `process()` needs 128-sample blocks; the old processor had no FIFO, reset the read pointer per frame and zero-filled when dry → ~5% hard silence, 75 dropouts/s, audible only to the remote peer. Fix: ring FIFO (`RING_SIZE = FRAME*4`) + `PREFILL = FRAME*2` before playout; on overflow drop the **oldest** sample, never reset the read pointer; on underrun re-prime. Pinned by `unit-rnnoise-worklet.spec.js`.
  - `getNoiseSuppressionMode()` still defaults to `'browser'` on `IS_MOBILE_DEVICE` (native app, mobile UA, or iPadOS desktop-UA with touch). That was a workaround for the bug above — worth re-testing on a real device.
  - Pin the worklet node to mono (`channelCount: 1, channelCountMode: 'explicit'`); `MediaStreamAudioDestinationNode` defaults to 2 channels.
  - `_cleanup()` in the worklet can run before `_initWasm()` resolves: guard the exports, and re-check `this._destroyed` after the `await`.
  - Send RNNoise WASM to the worklet as **raw bytes in a transferable `ArrayBuffer`** (`postMessage({type:'wasm-bytes', bytes}, [bytes])`, compile with `WebAssembly.instantiate(bytes, imports)` → `{module, instance}`). Posting a compiled `WebAssembly.Module` never reaches the worklet's `onmessage` (silent 5 s timeout, then raw-mic fallback).

## macOS / Tauri

- `make dev` does not register `voxal://`: run `make build-debug` once and open the `.app`; it persists.
- `src/build-info.js` (gitignored) is regenerated by `gen-build-info` before every native build and `cap-sync`, but NOT by `make dev` (stale in dev).
- Default PTT shortcut is `Shift+Space`.
- `settings.html` is a separate WebView: device labels stay generic until it gets media permission. **The `getUserMedia` label probe must never run during a call** — it reconfigures the shared macOS capture session and kills the main window's live mic and camera. Guards: skip while `localStorage['room-active']` is set (`publishRoomActive()` at join/leave); probe only the kinds with missing labels; don't set `_mediaLabelProbeTried` when skipped (a `storage` listener retries after the room ends). `room-active` is **cleared at `main.js` load** (leftover from a crash).
- Desk View / virtual cameras render a split frame with fixed `width/height` constraints → select by `deviceId` only.
- Native-only data (WebKit lacks `performance.memory`, `deviceMemory`, `navigator.connection`, `getBattery`): Tauri command `get_device_stats` (sysinfo, starship-battery, macOS shell-outs for Wi-Fi/Low Power Mode) fills the device-info panel. App-defined Tauri v2 commands need no capability entry (only plugin commands do).

## Android / Capacitor

- Custom plugin methods need `@PluginMethod` (`com.getcapacitor.PluginMethod`) or JS cannot call them.
- Android 12+ `AppOps` attribution warnings: declare `<attribution>` in the manifest and use `createAttributionContext(...)` before `AudioManager`/`NotificationManager`.
- Host-liveness checks must skip the host itself (it has no `connections.get(roomCode)`), or resume/foreground triggers false migration.

## Host migration & room membership (the rules that keep the room from splitting)

- **One primitive**: `connectToHost(hostId, { mode: 'initial' | 'migration' })`. `roomState` machine `idle/connecting/connected/migrating` makes triggers idempotent. Migration success = the new host's first authoritative `peer-list`, not the DataConnection opening. `mode:'initial'` must not require `inRoom` (it flips in `finishJoin()`). Audio `MediaConnection`s to non-host peers are never touched during migration.
- **Election follows the host-published successor chain** (`deputyId`, `successorIds` in every `peer-list` + heartbeat, `authoritativeSuccessorIds` on peers), never a local recompute from `connections.keys()`/live roster (links vanish transiently; `peer-left` delivery is asymmetric). Failed candidates go to `_migrationExcluded`; if the whole chain is gone, `leaveRoom()`.
- **Split-brain causes already fixed (keep them fixed)**: (1) host must `broadcastHostPeerLists()` after `peer-joined` for new peers too, or survivors' successor chain is stale; (2) `isCurrentPeerDataConnection` returns false when `!inRoom` (PeerJS fires `close` synchronously inside `leaveRoom()`, which broadcast a corrupted list); (3) a self-destroying host: defer the `peer-left`/roster broadcast one tick (`setTimeout 0`) and re-check `peer.destroyed`/`inRoom`/`isHost` (`peer.destroyed` is still false inside the sync close cascade); (4) survivors need a retry budget longer than the deputy's promotion (`HOST_MAX_RETRIES` 8, `HOST_RETRY_DELAY` 1500) — retry before re-electing, with a generation counter to drop stale events; (5) `peer-unavailable` for the current `_migrationCandidateId` while `migrating` fast-fails to `initiateHostMigration(id)` (exclude + re-elect), so a dead deputy is skipped instantly.
- Guard `initiateHostMigration(...)` with the specific disconnected host id (stale `close` from the dead host can arrive after election). The elected host may receive DataConnections before `isHost` flips: accept them; `MediaConnection.close` must not tear down a healthy `data` channel.
- **Roster must not flicker**: on `becomeHost()` don't prune ghosts — `ensurePlaceholdersForKnownPeers()` + `startMigrationSettle()`; during the 8 s settle `buildHostPeerList` uses `knownPeerIds`, then pruning resumes. `MediaConnection.close` keeps a placeholder for any peer in `knownPeerIds`. `peer-list` must refresh aliases even for peers with live media.
- Host publishes `peer-list`/successors only for peers with an **open DataConnection**; prune host-side ghosts then.
- Duplicate joiner connections: store the NEW connection in `connections` first, then close the old one; ignore stale callbacks; broadcast a fresh authoritative `peer-list` and have clients drop omitted peers. Include each receiver's canonical `selfPseudo`/`selfPseudoColor` in `peer-list` so names self-heal.
- Old room codes stay joinable: any peer can answer a misdirected joiner with `redirect` to the current host; only the deputy auto-promotes, and only when the host link is really gone.
- Heartbeat is bidirectional (host → peers to detect a dead host; peers → host to evict stale links). PeerJS may not emit `close` for silent drops.
- `peer-unavailable` once `inRoom` is non-fatal (side MediaConnection to a stale peer): warn, don't `showError`.
- **A dead host produces several `peer-unavailable` errors per `peer.connect()`** (broker answers each queued message with `EXPIRE`). The repeats land while the `createRoom()` fallback is still awaiting ICE (`inRoom` false). Fix: `joinRoom()` captures its own `Peer` (`joinPeer`) and ignores errors once `peer` is a different object; every fallback caller (`joinChannel`'s `recoverOrCreate`, `joinOrCreateByChannelName`, `attemptRejoin`) calls `discardJoinPeer()` (`createRoom()` does too).
- **A named (non-UUID) code must never reach `joinRoom()` directly** — it has no claim-the-slot fallback. Dispatch on `UUID_RE.test(code)` (incl. `_tryNativeAppThenJoin()`). The iframe `join` command's `roomCode` is a peer id by contract.
- Lazy mic (join muted): `peer.call`/`peer.connect` can return undefined → use `connectOutgoingAudioToPeers()`.
- Async work must re-resolve `connections.get(id)` after every `await`. "Is this peer sharing" is signaling state: never clear it from a transport teardown. A pre-set field can fake a "previous state" that never existed.

## Dev-mode diagnostics (device-info panel, remote logs)

- Browsers expose **no** per-process CPU; memory is Chromium-only (`performance.memory`, `deviceMemory` capped at 8 GB); arch/OS version need async `userAgentData.getHighEntropyValues` (Chromium only); laptop-vs-desktop is a battery heuristic; low-power/background state isn't exposed; `navigator.connection` caps at `4g`. Never add a busy-loop CPU sampler. Never `getUserMedia` just to fill the panel; read the existing track's `getSettings()`.
- Latency/loss come from WebRTC `getStats()` (works on every engine): the **viewer** fills them from its own `conn.webrtcStats`. On your own row use `_aggregateLinkStats()` (mean RTT, worst loss) — there's no single peer link.
- Collection is on demand only (`device-info-request/response` relayed by the host). Sharing needs explicit consent: `debug-share-device-info` = `accepted | declined | unset`; reply `declined:true` unless `accepted`. Banner `#debug-consent-banner` when host `debugMode` is on and consent is unset.
- **Remote debug logs are a separate consent** (`log-session-*`): per-session prompt `#log-consent-prompt`, nothing captured until Allow, auto-expires at `REMOTE_LOG_MAX_MS` (10 min) with a persistent `#log-share-indicator`; a `declined` device is auto-declined. Hook the **console** (not `devLog`) plus `error`/`unhandledrejection`; hold the capture off while flushing (`_logCaptureBusy`); backfill from `_devLogBuffer` on grant; viewer state lives in `_remoteLogSessions`/`#remote-log-panel`, not in the popover (`updatePeerList()` closes popovers); drop entries from peers with no active session.
- Anchored popovers: a flat `max-height: Nvh` is not a viewport fit — `_positionAnchoredPopover()` measures space, anchors `bottom` when opening upward, flips only when below is truly cramped, adds `overscroll-behavior: contain`. `position: fixed` popovers must NOT add `scrollY/scrollX` to `getBoundingClientRect()`. The stats popover must not be `pointer-events: none` (its click-inside logic and scrolling die).
- Stats polling must NOT be gated on dev mode (it feeds the adaptive jitter buffer and the peer dot's ICE colour).
- `.btn-ghost` is the destructive/quiet variant (red hover) — don't use it for neutral actions.

## Orientation

- Native apps are hard portrait-locked: iOS `Info.plist` `UISupportedInterfaceOrientations` (iPhone: Portrait only; iPad keeps Portrait + UpsideDown); Android `android:screenOrientation="portrait"` (keep the existing `configChanges`).
- Web adapts to landscape instead of locking (`screen.orientation.lock` rejects in a tab; counter-rotating the page breaks every width media query). Landscape reflow: `@media (orientation: landscape) and (max-height: 600px)`, scoped `html.is-web` + `body:not(.embed-tiny)` + `#screen-<name>.active` (a bare `#screen-x {display:grid}` would show an inactive screen). Room: header on top, peers (2/3) + talk column (1/3), side set by `handedness` (`data-hand` on `<html>`, set in the head script); Home: `1fr 1fr`. Override `.screen { max-width: 480px }` with `none` or the grid stays letterboxed.

## Web / CSS

- Embedded Voxal video needs `allow="camera; microphone"` on every ancestor iframe. iframe `postMessage` targets must match the parent origin (`parentOrigin`; `getAllowedParentOrigin()` falls back to `document.referrer`).
- Pseudo storage: `sessionStorage` on plain web (per-tab names), `localStorage` on Tauri/Capacitor.
- Scroll chains: `height:100vh; overflow:hidden` on body/`.screen`; only the scrollable child gets `flex:1; overflow-y:auto; min-height:0`. **Every flex ancestor in the chain needs `min-height:0`** (WebKit/iOS clips top and bottom otherwise; Chromium doesn't reproduce — assert computed styles). Mobile modals: use `100dvh` (with `100vh` fallback line) and `align-items:stretch`, not `100vh` + centering (header ends up above the visible top).
- Toast: `position: fixed` (not absolute inside a `.screen`), shown with `.visible` class. Status dot: CSS circle, not a glyph. Popover that must not stretch: `white-space: nowrap` **and** `width: max-content`.
- `z-index`: `document.body`-appended popovers are siblings of `.modal`, so they need their own z-index above it.
- Tiny-embed "pop out": `sessionStorage` is per-window on web.
- HTTP cache can poison anonymous-rooms lookups (and cache partitioning hides it): GETs there need `no-store`. Anonymous-rooms service semantics were probed live — read the code comments before changing them.
- Presence `room_id` is a **public** code — never post the peer id into it.
- ICE resolution is identity-scoped: re-resolve on sign-in/sign-out.
- Microphone permission cannot be persisted by the page; iOS is the sharp case (`mic-prompt-count`/`mic-hint-dismissed` drive the hint). In tiny embed, acquire the mic on join when the grant is already persisted.
- `settings.html` cannot borrow `main.js` (no module system): cross-window features use the `storage`-event bridge (see CLAUDE.md). A `storage` event never fires in the writing window; add new keys to the main window's `relevantKeys`.

## Testing (general)

- `main.js` is a flat classic script: top-level functions are on `window`, `var`/`let` state is global, so Playwright unit-tests pure logic via `page.evaluate` (`tests/e2e/_helpers.js`: `seedRoom`/`callFn`) with no bundler. Assign to `let` globals; mutate `const` collections. Each test gets a fresh page.
- `IS_NATIVE_MOBILE`/`IS_MOBILE_DEVICE` and similar `const`s are evaluated at load → stub `window.Capacitor`, `navigator.audioSession`, etc. with `addInitScript` before `goto`.
- An AudioWorklet module is unit-testable on the main thread: `fetch()` the file, define `AudioWorkletProcessor`/`registerProcessor`, `eval`, stub only the WASM surface.
- Settings controls live in sidebar sections hidden until their `.prefs-nav-btn[data-target=…]` is clicked.
- The settings modal's `#modal-settings-sidebar` is shown at EVERY width: a column ≥ 861px, a horizontal chip row above `.modal-settings-scrollable` below it (outside the scroller, so it stays put). `body.modal-sidebar-visible` still means "wide layout", not "menu visible" — the CSS display of the nav no longer tracks it. A narrow chip tap scrolls with `scrollRoot.scrollTo` one frame late (opening a card collapses the others), never `scrollIntoView` (it would also scroll the `overflow:hidden` modal).
- When a timing change breaks a test, check whether the test measured a proxy the old timing happened to satisfy (e.g. `incomingAudio` must count attached `<audio id="audio-…">` with a live track, not `conn.media`). Bisect with `git checkout <sha> -- src/`.
- `makePeer({ storage })` seeds `localStorage` before load (settings read once at load/first mic acquisition).
- Playwright only collects `*.spec.js`/`*.test.js` (helpers named `_helpers.js` are safe). `npm install` can bump `@playwright/test` and its Chromium build → `npx playwright install chromium chromium-headless-shell`. `npx serve` may exceed the 120 s `webServer.timeout` on a cold cache; a plain `python3 -m http.server` fails `unit-auth-callback.spec.js` (needs `cleanUrls`).
- Coverage: `entryFilter` must be set on the `CoverageReport` that calls `.add()` (per test) as well as on the one that generates; both share `tests/e2e/coverage-options.js`. `make coverage-rust` needs `rustup component add llvm-tools-preview` + `cargo install cargo-llvm-cov`.
- Host-election invariants: `unit-host-election.spec.js` — add a case whenever a migration edge case is fixed.

## Multi-peer mesh E2E (`make test-mesh`)

- Local PeerServer per worker (port `9100+workerIndex`) with `generateClientId: () => randomUUID()` (so codes match `UUID_RE`); **bind `127.0.0.1` explicitly** (the IPv6 wildcard throws `EAFNOSUPPORT` in containers). Each peer is its own `browser.newContext()`. App is pointed at it through `localStorage['peerjs-server']`.
- Required Chromium flags: `--use-fake-device-for-media-stream`, `--use-fake-ui-for-media-stream`, `--autoplay-policy=no-user-gesture-required`, and **`--disable-features=WebRtcHideLocalIpsWithMdns`** (else loopback ICE never connects).
- Assert convergence with ONE combined `expect.poll` (one host + one room code + roster), never sequential polls (they race through transient mid-migration states). Before killing a host, wait until survivors agree on a deputy (`waitForSharedDeputy`). `speak()` returns before MediaConnections form — poll `incomingAudio`.
- **A scene compile freezes a page for 5–11 s on SwiftShader** (every peer shares one GPU process; scene shaders compile synchronously), which outlasts the 7 s host heartbeat and splits the room though nobody left. A mesh test that draws scenes raises `HOST_HEARTBEAT_TIMEOUT_MS` for its peers (`mesh-keyed.spec.js`), and keeps the camera small and the scenes cheap.
- A top-level `function` in `main.js` can be reassigned from `page.evaluate`, and main.js's own calls then go through the replacement — the way to watch an internal step (the keyed test wraps `noteKeyedAck`) without adding a test hook.

## Outgoing audio quality ("they can't hear me / chopped")

- Damage lands on the **listener**; your own playback never shows it. Tuning lives in `main.js` "Audio quality tuning":
  1. **Opus fmtp via PeerJS `sdpTransform`** (`opusSdpTransform`, passed by `audioCallOptions()` to **both** `peer.call` and `call.answer`): `useinbandfec=1` (biggest anti-chop win), `usedtx=1`, `stereo=0`/`sprop-stereo=0`, `maxaveragebitrate`, plus `a=ptime:40` in the Opus m= section (`setOpusPtime()`). Parse, don't append: match the rtpmap line with `[^\r\n]*` (not `.*`), never string-replace bare `opus/48000`, merge into existing fmtp params, stay idempotent.
  2. **DTX is what makes a released PTT cheap** (PTT sets `track.enabled=false`, still feeding silence to the encoder): ~5 kb/s per link vs 33–46 without. Measured onset was no worse with DTX (91 vs 100 ms at 20 ms ptime; synthetic source, loopback). `a=ptime` is a **receiver** preference libwebrtc honours; 40 ms is the sweet spot (60 ms is *worse* in Chromium — re-measure before raising). Mixed-version rooms negotiate per direction. `_lossWindow()` waits for `AUDIO_LOSS_MIN_PACKETS` (50) before computing a rate (DTX makes loss noisy); counters going backwards restart the window.
  3. **Receiver jitter buffer** `RTCRtpReceiver.playoutDelayHint`: `AUDIO_PLAYOUT_DELAY_BASE` 80 ms, `AUDIO_PLAYOUT_DELAY_POOR` 200 ms on measured loss/jitter or as soon as the path is `relay`. Chromium-only (`'playoutDelayHint' in receiver`).
  4. **Sender `setParameters`**: `maxBitrate` + `networkPriority/priority:'high'`.
- Jitter-buffer setting (`jitter-buffer`): `auto` or 0–500 ms; precedence local manual → host push → adaptive (`effectivePlayoutDelay()`, `playoutDelaySource()`). It's receiver-side, so a host smoothing a room must push `jitterMs` (in `peer-list` + heartbeat; only while host dev mode is on; `sanitizeJitterMs()` clamps; absent = no-op, no protocol bump). The control is duplicated in `settings.html`; the key must be in the `storage` handler's `relevantKeys`.
- `getStats()` only describes what you **receive**. Loss that *they* see of your stream is `remote-inbound-rtp` (denominator `outbound-rtp.packetsSent`): `lossPercent` (↓) and `outLossPercent` (↑ — the one that diagnoses "they can't hear me"). `_collectPeerStats` must sample BOTH `conn.media` and `conn.audioMediaOut`; ICE type reports the worst path (relay > srflx > host). Keep cumulative totals, peaks and a 60-sample history (sparkline in the stats popover).
- **A redundant MediaConnection doubles your uplink** (one Opus stream per listener): `connectOutgoingAudioToPeers` skips a peer when `peerAlreadyReceivesOurAudio(conn)` (compare track identity + `readyState==='live'`). Known gap: simultaneous calls (glare) leave both connections; a naive tie-break close is unsafe because `MediaConnection.close` triggers the remote's `clearPeerMedia` → `detachAudio` — fix that to re-attach from the survivor first. The 2-peer case doesn't duplicate.
- Anonymous rooms are the worst case (they used to get the dead shared public relay). Treating `iceType==='relay'` as poor is a mitigation.
- **Settings read only in `getMicStream()` (`noise-suppression`, `mic-device-id`) need `reacquireMicForRoom()` after a change.** It must: `sender.replaceTrack` (no renegotiation, no glare), walk BOTH MediaConnections, inherit `audioTrack.enabled`, keep the old stream if re-acquire fails, tear the OLD stream down only after the swap (via `stopMicStreamFully`), serialise against `_micAcquirePromise`.
- **`applyRNNoise()`'s stream is a graph destination**: stopping its tracks releases nothing (real mic `_rnnoiseOriginal` keeps running; sources pile into the shared `_rnnoiseNode`). Release with `stopMicStreamFully()`, which calls the one-argument `_rnnoiseNode.disconnect(dest)` — a bare `.disconnect()` severs other consumers.
- **"Can they hear me?" audio check** (dev mode; `startAudioCheck(peerId)`, 2.5 s window, reuses the device-info relay + consent): the receiver reports **deltas** of `totalAudioEnergy` (decoded non-silence), `concealedSamples/totalSamplesReceived` (what NetEq invented, after FEC), `media-playout.synthesizedSamplesDuration`, and the `<audio>` element's `paused/muted/volume` (autoplay blocks no RTP stat can see). Never send `sinkId`. Sender-side `media-source.totalAudioEnergy` is required to tell "didn't arrive" from "didn't speak" (if unavailable assume we spoke). A null "before" sample is not a failure. Verdict precedence: playback faults > silence > concealment (<2% good, <10% choppy, else bad). Guards must key on *in flight* (`!_audioCheck.result`), and `showDeviceInfoPopover()` calls `cancelAudioCheck()` on open.
- **Network echo test** (Settings → Audio, "Test over network"): two relay-only `RTCPeerConnection`s through the real `fetchIceServers()`, capture via `getMicStream()`, both SDPs through `opusSdpTransform()`; the recorded artefact is the **returned** stream. `ontrack` fires on negotiation, not media flow → success is `inbound-rtp.packetsReceived > 0`. Relay-only ICE with no reachable relay stays in `new` forever (never `failed`) → use a timeout + candidate count. A muted `<audio>` sink zeroes `totalAudioEnergy` → measure loudness with an `AnalyserNode` on the stream (connect only to the source, never to `destination`). Blocked while `inRoom` (shares `_rnnoiseCtx`). Not ported to `settings.html` (no `fetchIceServers`/RNNoise there) — it points at the main window.
- ICE: prefetch `fetchIceServers()` on load for EVERY user (anonymous included) so join isn't gated on endpoint latency. `/api/ice-servers` is edge-cached (`CDN-Cache-Control`) but `Cache-Control: no-store` for browsers; client fetches with `cache:'no-store'`.
- **Anonymous TURN = our own `/api/ice-servers`** (`api/ice-servers.js`, short-lived Cloudflare TURN credentials; a relay key must never ship in `src/`). Keep ALL transports Cloudflare returns (`turn:…?transport=tcp`, `turns:`) — UDP-only filtering breaks exactly the firewalled users. Cache the minted credential server-side ~80% of TTL; per-IP rate limiting is best-effort. URL: same-origin on web, absolute `https://web.voxal.app/api/ice-servers` on native; override `anon-turn-url`. `api/*.js` is ESM (`"type": "module"`); helpers in `api/_turn.js`; run `node --test "api/*.test.js"` (not `node --test api/`).
- Relay status must be source-aware (`turnStatusSummary()`: `embed/org/metered/anonymous/fallback`; the built-in fallback is demoted to a warning; before first resolution say "Checking relay…"). `· verified` only after a Test-over-network run whose `iceType` was `relay`.
- **The built-in fallback TURN (`DEFAULT_FALLBACK_TURN`, metered `openrelayproject`) is dead** (credentials retired). `onicecandidateerror` says why: 401/403 = rejected, 701 = unreachable, none = UDP black hole; `diagnoseRelayFailure()` maps them and short-circuits to "built-in relay retired".
- **Cloudflare Workers cannot host an echo/media service** (V8 isolates, no UDP/ICE/DTLS). The only Cloudflare option is Realtime SFU, which **decrypts** media — rejected for **audio**, permanently. It is used only for optional camera/screen video (`docs/video-routing.md`); voice/PTT never touches the SFU.
- **SFU video (Cloudflare Realtime) rules**:
  - `selectVideoTopology()` is the enforcement point: `mode:'sfu'` only when the user chose `allow-sfu`; never for `prefer-p2p` (reports a degraded P2P decision) or `p2p-only`. Threshold is its own `VIDEO_SFU_THRESHOLD_PEERS` (2), not the audio warn constant. A preference allowlist must name every valid value (the old default `prefer-p2p` once fell through and was silently overridden back to the relay).
  - Backend `api/sfu-session.js` / `sfu-track.js` / `sfu-renegotiate.js`: HMAC-signed short-lived capability token bound to `{roomCode, participantId, kind, action}`; secrets never reach the client.
  - A connected SFU session proves nothing about media: routing is driven by `tracks[]` in `tracks/new`. A subscriber must NAME the remote track (`{location:'remote', sessionId, trackName}`; carried as `providerRef` in `video-offer`/`screen-offer` and `peer-list`); a remote pull is answered with an **offer** (`requiresImmediateRenegotiation`) that the client answers via `sfu-renegotiate`; per-track failures are in `tracks[].errorCode` inside a 200 (`cloudflareTrackError()`).
  - The SDP offer goes on `tracks/new`, never `sessions/new` (which takes no body — `{}` ≠ no body; `callCloudflare()` omits body and content-type).
  - Test proxies by asserting the outbound request (stub `globalThis.fetch`, see `api/sfu-track.test.js`); pure-helper tests miss malformed bodies. Verify a new test fails against the pre-fix code.
  - A topology decision is not a migration: tear down the losing path (`unpublishLocalTrack()`, viewer-side mesh stream) when switching; re-run on roster change via debounced, memoised `reconcileVideoTopologyForRoster()`.
  - Cache the capability token for its TTL **and the in-flight promise** (30/min per-IP limit is the wrong axis for NATed rooms); report 429 distinctly from 503.
  - Anything driven by the `peer-list` broadcast must be idempotent (route through `applyRemoteTrackTopology()`'s unchanged-`{mode, ref}` guard; verify against real live state, not remembered metadata).
  - Byte-rate deltas are per `RTCPeerConnection` (`_pcByteCursors` WeakMap); first sighting reports zero.

## Robustness, scale, protocol

- All incoming peer messages are untrusted: reject non-objects, guard fields, route non-host dispatch through `safeHandleHostMessage()` (try/catch). (`unit-robustness.spec.js`)
- Audio is a full mesh: O(n²) links and one uplink stream per listener. No hard cap; `updateRoomSizeWarning()` shows a soft banner at `ROOM_SOFT_WARN_PEERS` (8) and hard at `ROOM_HARD_WARN_PEERS` (12), counted from `#peers-list .peer-item`.
- ICE precedence in `fetchIceServers`: (0) embed `postMessage {type:'config', iceServers}` → (1) org TURN → (2) metered `localStorage` → (2.5) anonymous `/api/ice-servers` → (3) STUN + `DEFAULT_FALLBACK_TURN`. Override step 3 with `turn-fallback`. STUN is not firewall traversal; TURN over TCP/443 / `turns:` is. A relay only forwards DTLS-SRTP so it never hears audio.
- Embed `config` is in-memory only, origin-validated (`?parentOrigin`, `getAllowedParentOrigin()`). `isTrustedParentMessage(e)` gates all iframe commands only when `parentOrigin` was declared; `config` is strict regardless.
- `PROTOCOL_VERSION` (int, in `hello` + `peer-list`) bumps only on wire-protocol changes; keep changes additive/tolerant (missing = `0`, ignore unknown) because mixed-version rooms must work. Updates: web latest; Tauri updater (signed `latest.json`); mobile **Capgo OTA** (`notifyAppReady()` auto-reverts crashes) — JS changes ship without store review, native-shell changes need a release.

## Video stage (desktop + phone)

CLAUDE.md describes the final shape of the phone stage chrome; this keeps the gotchas behind it.

- **Strictly additive**: `body.video-stage` (and `video-stage-immersive` / `video-stage-desktop`) is set by `updateVideoStage()` only while a camera or screen is genuinely live; an audio-only room must render byte-identically (`unit-video-stage.spec.js`). Publish the mode as a body class instead of re-deriving it in a media query. `videoStageMode()` → `'none' | 'desktop' | 'immersive'` (native = immersive at any width, because a portrait tablet would trip the desktop breakpoint; `videoStageAvailable()` is the derived boolean; Tauri is `is-web` + `is-desktop-app`).
- Desktop stage reuses the landscape technique: named-area grid re-assigning existing nodes (`stage | rail`); needs `max-width: none`; declared after the landscape block, whose selectors are `:not(.video-stage-desktop)`. Anything that can appear above the room (e.g. `#debug-consent-banner`) needs its **own grid row** — two items in one grid cell stack.
- **`auto-fit` can't lay out a conference grid** (knows nothing about leftover height). `bestGridColumns(count,w,h,aspect)` + `layoutVideoStageGrid()` write inline columns, recomputed on `resize` (rAF-throttled). Measure the **content box** (subtract the inset), not `getBoundingClientRect()` (border box).
- **Score what is displayed**: cell area × fraction of the frame surviving the `cover` crop; charge a cell *wider* than the frame fully (crops head), one *narrower* at the square root (crops background, subject larger). That yields 2×2 for four faces on a phone, not four 390×140 strips. Ties are common: within `STAGE_AREA_TOLERANCE` (20%) prefer balanced `|cols−rows|`, then the extra column. An incomplete last row is centred with a doubled track count (`repeat(cols*2,1fr)`, tiles `span 2`) — so count columns by the widest row, not distinct `left`s.
- **Capacity**: `stageGridCapacity()` caps the grid (4 on phone, 12 desktop, lower if cells fall under `STAGE_MIN_TILE_W/H`); the rest go to the overflow **ribbon**. To avoid a capacity↔ribbon feedback loop `stageGridBox()` adds `STAGE_RIBBON_RESERVE` back and `stageGridCapacity()` subtracts it once. Membership = screen share, then most recent speaker (`_speakerRecency`), **sticky** via `partitionStageTiles()` (one press = one swap); `noteStageSpeaker()` re-renders only if the talker is in the ribbon. Bottom clearance belongs to the last thing in the stack (the ribbon, `--stage-ribbon-height`). With a focus tile (screen share) there is no ribbon. The "+N" pill is scroll-derived (rAF-throttled), styled as a chip, not a gradient.
- **Reconcile by key; never rebuild.** `updateVideoStage()` runs at the end of `updatePeerList()`. Reassigning `video.srcObject` restarts playback and flashes: `_syncVideoTile()` assigns only on change; tiles are **moved** between grid/badge/ribbon, never rebuilt (`srcObject` descriptor lives on `HTMLMediaElement.prototype`). A stubbed stream must be a real `MediaStream`.
- Every tile is `muted` (audio has its own pipeline). Self-view camera is mirrored (`scaleX(-1)`, camera only; conditional on `data-facing` so a rear camera isn't mirrored); a screen share is never mirrored and always `contain`. A peer whose camera is on but stream not yet arrived keeps a placeholder slot.
- **Roster camera icon** stays for everyone with live video and its meaning must not change under the user: `togglePeerVideoWatch()` branches on `videoStageAvailable()` (media query), never on whether the stage currently has tiles. Hiding a peer is local (`_hiddenStageKeys`, not persisted, cleared in `resetVideoState()`, released when the source disappears); on your own row it toggles self-view only (`camera:self`), never the stream.
- **Self-view badge** (`#video-stage-self`): minimised when another *camera* tile is visible (`selfBadgeTileKey()`; explicit pin wins). Stored as edge + fraction along it (`left:0.42`, `self-video-corner`, `:tuck` suffix; see CLAUDE.md). `selfBadgePlacementFor()` and `selfBadgeOffsets()` are exact inverses through `_selfBadgeTravel()`. Offsets are inline from measurement; call `applySelfBadgePlacement()` at the end of `renderVideoStage()`; never clear inline offsets before re-placing (visible jump). Drag: `touch-action:none` alone isn't enough (the press may start on the control bar, `selfBadgeAtPoint()`) → non-passive `touchmove` preventDefault during drag + `touch-action:none` on the bar (`body.self-badge-on-bar`) + `setPointerCapture()` only after `SELF_BADGE_DRAG_SLOP` (earlier capture steals the tile's click). `pointercancel` restores, not commits. Listen on `window` for move/up. Swallow the click after a drag (capture phase). Tuck: dragging past a border by `SELF_BADGE_TUCK_MIN` leaves `SELF_BADGE_PEEK` showing as a handle (tap = bring back).
- The flip button belongs ON the self tile (moves with it between grid and badge): `stopPropagation` on `click` and `pointerdown`, counter-mirror itself.
- **Flip is not stop**: `flipCamera()` acquires first, keeps the old stream on failure, `replaceTrack`s every live sender (mesh `videoMediaOut` and the SFU pc), stops the old stream last, re-runs `tuneVideoSenders()`; it must send **no** message (`video-stop` would delete the tile for everyone). On phones facing mode outranks a stored `deviceId` (`selectedCameraConstraints()` branches on `IS_MOBILE_DEVICE`).
- **Video sender tuning**: `tuneVideoSenders(pc, kind)` sets `maxBitrate`, `degradationPreference`, `contentHint`, `scaleResolutionDownBy` stepped by peer count. Screen = `maintain-resolution` + `contentHint:'detail'` (never scale); camera = `balanced` + `'motion'`. Capture caps are `ideal`/`max`, never `exact`. PeerJS creates the `RTCPeerConnection` asynchronously → `tuneVideoCall()` applies next tick and again on `stream`; answering handlers (`new MediaStream()`) have no video senders to tune. `cameraMaxBitrate()` returns the **mobile** cap whenever `IS_MOBILE_DEVICE` (WebKit has no `navigator.connection`) and only lowers it further on `saveData`/2g/3g.
- `video-mode-enabled`: read via `readVideoModeEnabled()` (absent = on; only explicit `'false'` disables). Never force-write it.
- Pause a backgrounded camera with `track.enabled=false`, never `stop()`; drive from both `visibilitychange` **and** Capacitor `appStateChange` (iOS may suspend before `visibilitychange`). Wake lock: track intent (`_stageWakeLockWanted`) separately from the sentinel and re-request on `visibilitychange` (sentinel auto-released when hidden).
- **Android needs `android.permission.CAMERA`** in the manifest (else `getUserMedia({video})` is auto-denied in the app) plus `uses-feature camera/autofocus` with `required="false"`. Do NOT add `camera` to the foreground service type. iOS already had `NSCameraUsageDescription`. Manifest change needs a Play build (rest is OTA).
- Turning a camera on is not a decision about the microphone: `startVideoShare()` must not latch hands-free (only the `?video=1` link does, in `autoStartVideoOnJoin()`; screen share still latches).
- The talk hint follows the **device**: `IS_MOBILE_DEVICE` in `setFreeHand()` and at startup (a PWA runs the web build): "Hold the mic to talk · x2 for hands-free".

- Stage is `inset: 0` on `#screen-room`; an absolutely-positioned child is laid out against the **padding box**, so don't offset by the safe-area padding (it overshoots by twice that). Assert `stage rect == room rect`.

A header that is a grid row hides with `visibility`, never `translateY(-100%)`. Talk button takes the bottom of the room, full width, buttons on one line; a centred flex row centres the group not the mic → `1fr auto 1fr` grid with the mic in the middle track. `visibility:hidden` reserves width too → hint/status are `display:none` sideways.

- Glass: scoped to `body.video-stage-immersive`; tint dark in both themes (`--glass-tint/--glass-sheen/--glass-blur`); controls get light-on-glass overrides; the talk button keeps its accent ring and states. There is **no slab** — each control carries the glass. A control that relied on the slab needs its own dark tint and `text-shadow`.

Use `visibility:hidden`; use `border-top-color: transparent`, never `border-top: none`. `.ptt-status:empty{display:none}` would move the mic whenever the room has news — it reserves its line. With chrome away the mic alone drops by `translate: 0 var(--ptt-drop)` (not `transform`, which holds the press scale); code reading the mic rect must take it back out (`pttLayoutBottom()`).

The bar forwards taps on its bare background both ways (`initStagePanelHandles()`; `_stageTapOnChrome()` exempts real controls). Clear `body.stage-chrome-hidden` whenever the stage stands down.

- Two old tests used "narrow viewport" as a stand-in for "no stage"; when behaviour changes, check whether a test asserted mechanism or intent.
- Test traps: `transition` on a panel makes `getComputedStyle` a race (poll: `pickSettled()` in `unit-video-mobile.spec.js`); when walking `document.styleSheets` test `rule.selectorText` before `cssRules` (nested CSS gives style rules an empty, truthy `cssRules`); `getComputedStyle(el,'::before').display` is `block` for a pseudo that doesn't exist → check `content`; a button pinned under the header is only caught by a **click** test.

## Phone tilt (`device-tilt.js`, the tilt strip)

- **Build a rotation matrix from `deviceorientation`; never use alpha/beta/gamma as the turn.** An upright phone (a selfie) is next to the Z-X'-Y'' singularity (beta ≈ 90°), where alpha and gamma swing while the pose barely moves. Decompose only the small *relative* turn (`Ry Rx Rz`) afterwards.
- **Front camera: image-right is the screen's LEFT, forward is out of the screen.** The published frame is unmirrored (only the self-view is). Screen rotation (`screen.orientation.angle`) is a local `Rz(-a)` on the device frame. Camera change → new baseline.
- **Scene shaders mirror the room for a light on the left by mirroring `p`** (`shade(p, m)`), so a view turn must be applied in screen space (`viewFwd`/`viewInv` un-mirror with `MIR`), or a right turn moves the room the wrong way on half the lights. Anything drawn in the picture's plane (countryside grass, chimney smoke) must follow `viewShift()` / `viewInv()` or it stays glued to the glass.
- **The turn rides in the keyed frame (a luma strip), not a message**: messages between non-hosts ride the host (≤2 offers/s), and a frame carries its turn exactly in step with the person. The strip must be reserved by the receiver only when the *offer* says so, and the offer's `tilt` flipping is a **new epoch** — otherwise a receiver can be on the keyed track while the cells land as picture. A sender draws it only if every keyable peer has `keyed-tilt-1` (one picture for all).
- **A sum check like `y + 3p + 5r` misses flips of any bit whose weight is a multiple of 64** (found by the test, not by thought). XOR the data's 6-bit groups instead: every single-cell flip changes it.
- **iOS prompts for motion only from a user gesture**, long after the scene chip was tapped; `armTiltGesture()` asks on the first tap while the sensor is wanted but silent. A WebView that never delivers an event leaves `DeviceTilt.ready()` false and the app unchanged. `NSMotionUsageDescription` is in `Info.plist` (store build). Not yet checked on a real device.
- Four scene-**preview** tests (`unit-scene-light` 172, `unit-scene-orbit` 433/572/660) stall the page on CI's SwiftShader and time out every run (red main since #215), yet pass on a real GPU and locally under SwiftShader flags. Quarantined with `@slow-gl` into the `gl` project (`npm run test:gl`, non-blocking mesh job). Docs-only PRs skip `E2E (unit)`, so a red there can hide for several merges. Fix: the preview loop draws at `PREVIEW_SOFT_FPS` (2) and skips its cost probe (3 redraws + `gl.finish()`) when `soft` — only the tests reach it, production refuses a software GPU. Passes locally; confirm on CI. **Confirmed not enough:** skipping the probe left the non-quarantined "names the scene…" test waiting forever for a measured figure (red on main after #233/#234). A software GPU now reports "not measured: this device draws scenes in software"; the measured-number assertions live in their own `@slow-gl` test. Rule: a gating test must never assert something a software GPU cannot produce.
- Tests on this machine: `unit-video-keyed.spec.js` "a green subject withholds keying…" fails on a clean `main` too (`slow-copy`: this GPU's keyed copy is over its 4 ms budget); the scenes spec's afterEach can time out under 3 parallel workers and passes alone.

## i18n

## Segmentation diagnostic (`VideoEffects.openDiagnostic()`, `docs/video-effects.md` → *Looking at the cutout*)

- **Debug uniforms live in the program, so "frame with panel open == frame after closing" proves nothing.** `uDbg` left at 1 made BOTH frames print the matte and the test passed; only a baseline drawn *before the panel was ever opened* catches it (found by mutating the reset away). Also run the mutation on a layout where the debug pane is the LAST draw (`matte` alone): in `stages`/`grid` the final pane resets the uniform and hides the bug.
- **MediaPipe's callback form of `segmentForVideo` returns synchronously** (`vision.d.ts`), so the frame `draw()` uploads right after is the frame the inference saw; the panel prints the video-clock skew (0.0 ms measured on the real model). The mask is only valid inside the callback: copy what you need there.
- The shipped `selfie_segmenter_landscape.tflite` returns ONE confidence mask, label `["selfie"]`, 256x144 for a 16:9 camera; high = person.
- **`gl.finish()` is not a timing fence in Chromium/SwiftShader**: a 720p draw "took" 0.09 ms. Force completion with a 1-pixel `readPixels`, and expect it to be slow enough that a 120-iteration loop times out; keep software-GL micro-benchmarks to ~25 iterations.
- **The selfie model's unsure pixels are 20–70%, not 0/1** (phone selfie: lamp over the head median 48%, shoulder rim 62%, hair edge 41%). The composite's 12–78% window kept those partly visible; the raw mask is now cut at `MASK_CUT` (78%) in `FRAG_MASK_MIX`. Thresholding cannot separate a lamp from hair (same confidence), so the cut costs fine hair — that is the user's accepted trade. `?maskcut=` compares on a device.
- Don't `pkill -f "<pattern>"` with the pattern in your own command line — it kills the shell running it.

## Camera background effects (design in `docs/video-effects.md`)

- A canvas that is never redrawn emits one frame (`captureStream(15)` over a static fill): fake cameras in tests must repaint on an interval (`unit-video-effects.spec.js`).
- `import('assets/seg/x.mjs')` throws (bare specifier) — use `./assets/…` or an absolute URL; `video-effects.js` runs every runtime path through `new URL(u, document.baseURI).href`.
- MediaPipe's `canvas:` option takes over that canvas's GL context and resets its state: give it a throwaway canvas and take the mask back as a `Uint8Array`.
- `@mediapipe/tasks-vision` unpacks to ~36 MB; the SIMD build used (`vision_wasm_internal.{js,wasm}` + `vision_bundle.mjs`) is ~12 MB. The npm package has no `.tflite`: `selfie_segmenter_landscape.tflite` (250 KB) is vendored from `storage.googleapis.com/mediapipe-models/…`.
- `ImageSegmenter` returns the mask at the size of the frame you pass → downscale the frame yourself first (check `mask.width/height`), or you resample into a wrong aspect and clip the subject. A confidence mask from `getAsUint8Array()` is 0–255; the selfie model has ONE mask (check `getLabels()`; other models put the person at index 1).
- Every mask stage erodes the subject (feather, smoothstep, lag): dilate before feathering and bias the threshold low. Temporal blend must be asymmetric (grow ~0.85, shrink ~0.2).
- The static site is `web.voxal.app`; `presenceBase()` is NOT it (default is a Supabase function). Anything a native build fetches from the site uses the override-key + same-origin-on-web + absolute-on-native pattern (invisible on web, breaks apps).
- A file input must be `.click()`ed **synchronously in the gesture** (any awaited promise spends the activation; WebKit then silently does nothing); hide it with `opacity:0` + 1px box, not `display:none` (WKWebView).
- `overflow-x:auto` clips vertically too (rings, outlines, badges): pad the container, pull back with negative margin. `Content-Length` is the compressed size (progress > 100%): treat as a hint and clamp. `captureStream(0)` + `requestFrame()` isn't in Safari: feature-detect, fall back to `captureStream(fps)`. Vercel caps `buildCommand` at 256 chars (schema validation error) → `sh vercel-build.sh`.
- **No frame callback on a `<video>` across a `srcObject` switch until the new stream has a frame** (Chromium 141 kills the tab, "Target crashed", SIGSEGV in `WebMediaPlayerMSCompositor::GetLastPresentedFrameMetadata`). A `requestVideoFrameCallback` asked for inside one, with the switch in that same task, sends Chromium's next frame lookup to the new player, which has none yet → null. main.js does exactly that (it hands a fresh key-in handle its stream in the promise a frame callback resolved), and only same-task switches crash, hence a 1-in-5 flake. Cancelling is not enough — a callback asked for just after the switch crashes too — so `repointVideo()` cancels, holds the loop (`_held`) and polls `videoWidth && readyState >= 2` before re-arming. A repro needs a frameless stream: `captureStream(0)` of a canvas painted only after the capture (a painted one hands over its picture at once).

## Animated scenes (shaders, `video-scenes.js`)

Design: `docs/video-effects.md`. Preview any scene/look headlessly with `make scene-preview` (`scripts/scene-preview.mjs`, SwiftShader runs WebGL2) — judging pictures caught more bugs than unit tests.

- GLSL / JS: the shader's alpha carries surface distance (for the subject shadow), so any canvas that only displays a scene needs `alpha:false` (else far surfaces export transparent/white). GLSL ES 3.00 reserved words bite (`patch`, `cast`, `half`, `sample`, `input`, `output`, `filter`). A **backtick in a GLSL comment** ends the JS template literal (`node --check` finds it). Avoid `pow(x,2.0)` with negative x and `smoothstep` with edge0 ≥ edge1 (SwiftShader forgives, real drivers return NaN) → use `sq()` and the scene's own `sstep()`.
- Compile cost is the JIT, not the pixels (software GL, no `KHR_parallel_shader_compile`: ~1–4 s per scene). Thumbnails render only when the chip row is visible (`IntersectionObserver`), one per task with a delay, via `OffscreenCanvas.convertToBlob()`; on software GL (`VideoScenes.isSoftwareGL()`) skip them (tests opt in with `window.__voxalThumbsOnSoftwareGL`).
- Lighting: measure the illuminant on the **room** (gray-world over the frame, follow it halfway and clamp), exposure on the subject's confident core. Direction (window side) needs hysteresis (±0.35) and a ~1 s crossfade between mirrored layouts; scenes carry no text/clock (mirror). Night scenes must still be a picture (~28/255 mean, not 20). Physical-ish units need an exposure (`main()` ×0.55 before the ACES shoulder).
- Noise: one 256×256 `RGBA8` lattice texture (`noiseTexture()`, seeded in JS, texture unit 8 because the pipeline's `texture()` helper binds to the *active* unit; `setUniforms()` restores it) beats hashing (~35% faster). The test forbidding `sampler2D` means "no picture".
- Ray-march traps: over flat water the step floor is distance-proportional (steps = `ln(range/t0)/ln(1+grow)`); an exhausted march must not "hit" (painted the lake bed over the lake) → separate short near-field march, start the expensive one ~1 km out. Refine skyline AA around the nearest sample (golden-section) and treat a refined value < 0 as a hit. Domain-repeated objects need the neighbouring cell too, and a step cap only in the march (global set/cleared), never in `map()` (grey halo from AO/normals).
- Motion is a bitrate cost for every receiver: slow and sparse, redraw below camera rate (20 Hz, per-scene `res`/`hz`), scale wave phase speed down ~20× and fade sub-pixel octaves, keep palm sway to a few hundredths of a radian; pinned by a test (mean change between frames a second apart < 3/255). That test sees one unjittered redraw; what the resolve adds per redraw is pinned apart.
- **Blurring a scene to save bits was the wrong trade: people want it sharp.** A depth "lens" cut VP9 motion cost 50–83%, and the owner rejected the look. The scenes are now jitter-accumulated to the camera's size (`RESOLVE_FRAG`). Detail that holds still costs a keyframe once; what moves costs every frame, so if bits matter, calm the motion rather than blurring. Measure with `make scene-preview ARGS='--bits --person'`, never by eye. Scene alpha is a shadow-receiver weight that reads as nearness (walls ~0.95, sand ~0.55, sky/sea/mountains 0).
- **Jittered accumulation (TAA-style upscaling) of a fixed camera:** detect movement by comparing the redraw and the history *through the same blur at the same points*, never point sample vs history. Point vs history flags every static edge as moving, so edges never converge. Use a long Halton sequence (256 points, not 16); a short one looks at each output pixel from the same side and edges come out dotted. Give alpha (nearness) its own tolerance, since it jumps at edges where the colour does not. Count early looks heavily (`1/(1+age·coverage)`) or a new pick stays soft for seconds, but keep the steady share small (0.1): at 0.25 a settled picture never settles, and a scene frozen in time cost 43–76% of a moving one in VP9 bits. Measure with `--bits --still`. Judge colour apart from brightness (YCoCg, wider colour tolerance): a relight can change only the colour, and testing each RGB channel alone flags single-channel march grain as movement (+50% frozen churn).
- In a test, putting RGBA with alpha < 255 into a 2D canvas premultiplies it, and the RGB comes back changed. Force alpha to 255 before `putImageData` when you only want the colour.
- **A "linear-light" blur through `texture()` is not one**: the bilinear filter averages in sRGB before your shader squares, and at radii of ~1 px that is most of the blur (1-px black/white stripes came out 149/255, not ~180; found on the scene lens, since removed). Fetch both texels (`texelFetch`), square, then mix.
- A mipmapped texture with only level 0 defined is **incomplete and samples black** (also via `texelFetch`): `generateMipmap()` once at allocation if anything reads it before the first per-frame regeneration.
- `VideoEncoder` exists only in a secure context: a Playwright page on `about:blank` has none → `page.route('https://x.test/**')` + `goto`. This Chromium has VP9/AV1 `bitrateMode:'quantizer'`, not VP8.
- Scenes on a software GPU make the bench's camera rows stall (no decoded frame within 45 s) when anything else is using the CPU, and the effect gives up mid-run anyway; the scene rows (`preset:office`, `preset:island`) only mean something on a real GPU.

## Detection controls

- The mask's working size is NOT an accuracy knob (`ImageSegmenter` resizes to the model's 256 input). The honest knob is the inference **rate** (mask lags by one interval); `detection-quality` picks a rate ladder `[start, …, 6]`. Switching restarts at the top and resets the measurement window; hand out a **copy** of the ladder (the processor mutates its position).
- Feather radius, the composite `smoothstep` window and `MASK_DILATE` are ONE control (`_edgeProfile()`; softer dilates further). A narrow window on a wide feather is a hard edge (now `MASK_FEATHER 1.4`, `smoothstep(0.12,0.78)`, `MASK_DILATE 3`). Pin the slider midpoint: a test asserts `_edgeProfile(0.5)` equals the four tuned constants.
- Low light: brighten only the segmenter's private 256-wide copy via canvas `ctx.filter` `brightness() contrast()` (never the published frame; feature-detect `typeof ctx.filter === 'string'`). Measure the **centre** (12×8 probe) not the frame (backlight), ease gain 25% per sample, clamp `[1, 2.6]` (gain 1 sets no filter), and read luma from a separate canvas fed by the `<video>` (no feedback loop).

## Fixed camera (empty-room reference)

- Protect an **erosion** of the mask (4 texels) from the reference, not a threshold of it. Compare like with like (same 4-tap sampling for camera and reference). Compensate auto-exposure/white balance with a per-channel gain measured over what the model calls room (64-wide probe, 2×/s). The reference gives up by itself: set aside below 55% match, trusted again above 70%. It can only **take away** (`m * max(diff, core)`), never add. Switching off forgets the picture; it's never stored.
- The capture guide's flash and any bright UI change must come **after** `captureReference()` resolves: the screen lights the room, so a white frame mid-capture is learnt as the room's colour. Keep the scrim identical from countdown to capture end. While the user walks away, focus the dialog, never a button — Space is PTT and also clicks a focused button. Beeps run from a timer, so resume `_audioCtx` in the click that starts the guide (iOS refuses later).

## Background blur quality

- **A separable kernel that doesn't sum to 1 is a brightness multiplier** (a typo'd 9-tap summed 0.838 → 70% brightness after two passes, and capped the mask feather at 0.7). Weights come from `gaussianHalfKernel(sigma, taps)` now.
- Blur in linear light (gamma 2.0: multiply and `sqrt`), keep the intermediate buffer sRGB-encoded (8-bit linear bands), but never linearise the mask feather (coverage isn't light) → two programs from one generator.
- Downsample with 4 taps (box filter), not one bilinear tap; blur at a **fixed buffer size**, not a fraction of the frame; reach big radii with **doubling strides** (variances add: N passes ≈ `sqrt((4^N−1)/3)`×) with the first stride under a texel; derive the pass count (2 at the bottom of the range, 5 at the top). Strength is one value (sigma / long side); the slider is geometric (`MIN*(MAX/MIN)^t`).
- **A feedback filter must never read the buffer its own post-processing wrote**: the blend's `uPrev` was the finished mask, so dilate+feather compounded ~15×/s (50% point 10.7 texels outside the subject — it presented as "blur not strong enough"). Two ping-pong pairs (blend memory vs derived mask). Lesson: when turning a knob up doesn't work, measure the thing it feeds; test the steady state (early vs late inference), and test arithmetic AND picture (probe a blurred black/white edge; `unit-video-effects.spec.js` runs the real GL pipeline with `window.__voxalSegStub`).
- **Decontaminate the edge by colour, not by the matte's alpha**: the matte is dilated and feathered, so `F = (I - (1-m)B)/m` over-corrects pure person pixels inside the band (contrast halo). Project the pixel onto the line between a person tap (inside) and a room tap (outside) instead: `t` is 1 for pure person, so only genuinely mixed pixels move. A flat room is the control (`fg` = `bk`, nothing moves).
- **Judge scene sharpness with `make scene-preview ARGS='<scene> --live'`, not the default**: the default draws every redraw at one frozen moment, which is the best case — whatever MOVES (a palm, the shoreline) is not added up by the resolve and shows as one stretched buffer. That, not the settled picture, is the 'SD and blurry' look in a call; the fix is buffer size (`SCENE_SCALE`), not resolve tuning. Buffers are capped at the camera's size, so a small test camera cannot tell the scale steps apart.

## Keyed camera ("Let others draw my scene"; design in `docs/video-effects.md`)

- **Decoded green is not the green you sent.** Limited-range YUV, a matrix mismatch and 4:2:0 move `(0,255,0)` off pure key, differently per decoder → never key against the constant: the receiver reads `kd` from the top-left marker's taps every frame and keys against that (`a0 = 1 − e(c)/max(e(kd),0.3)`, `e = g − max(r,b)`).
- **Copy a GL canvas into a 2D canvas in the same task as the draw.** With `preserveDrawingBuffer:false` the back buffer holds the frame only until the task ends; that is what lets one program draw keyed → `drawImage` → the composite over it, the GL canvas still publishing the composite. Where the 2D canvas is not GPU-backed the copy is a synchronous read-back out of the pipeline's own budget → it is timed (median of 30 > 4 ms withholds keying) and drawn only while a sender reads it (`setKeyedDemand`).
- **Release every WebGL context with `WEBGL_lose_context.loseContext()` (and zero the canvas) on destroy.** Chromium force-loses the OLDEST live context past 16 — after a few receivers come and go, the user's own camera pipeline — and its captured track stays `live`, frozen for every peer. The local `Processor` also answers `webglcontextlost` with `giveUp('context-lost')` (effect off, plain camera) rather than freeze. Pinned: 20 `keyIn` create/destroy cycles keep the local context alive.
- **An ack must name the call and the epoch** (`video-keyed-ready {call, epoch, scene}`; `call` = the `MediaConnection`'s `connectionId`, which PeerJS gives both ends). An anonymous "ready" let a stale yes key a fresh call the receiver had no cut-out for (camera restart, a re-call after migration) = raw green. Around it: every new call starts on the composite, acks repeat every 10 s and expire at 25 s, `hello` re-carries the offer to each new host, and a receiver finishes closing only on positive evidence (an unkeyed frame after its `ok:false`), never a timeout — a lost `ok:false` then ends in a green tile.
- **Detection must know what it expects.** At a composite→keyed switch on a starved link the black patch's chroma settles frames after the flat green, so a strict-only detector passes those frames through as a full-screen green flash. Strict (TL key, TR ring key, patch dark) while not expecting; relaxed (TL key, patch not key) while acked or within 500 ms of a STRICT pass — a relaxed pass renewing its own window latches onto any picture with a green top-left corner. The patch is black (luma survives 4:2:0), not grey: markers found in 50/50 frames through VP8 at 320×180 96 kb/s and 160×90 38 kb/s; the switch at 60–112 kb/s showed no key-coloured frame.
- **Score a key on colour against the sender's composite, never on alpha.** `a0 = m·(1 − e(camera))` saturates before `m` for anything redder than green (a face), so the first formula left a lime rim — band p95 36 (no codec) / 42 (VP8 450 kb/s) — while its alpha error looked fine. The sender's `edgeE` (median `e(camera)` over its band) divides it back out within ~10 px of background only: mean 6.9 / p95 13.0, and 12.5 / 27.2 through VP8 (Chromium 141 — 156's encoder gave 32 on the same code, so a codec-path bound measures the browser: pin the formula on the no-codec number). A mask band packed into the frame instead cost ~60 kb/s.
- **Withheld keying = the plain composite on the keyed track**, unmarked, so receivers pass it through and nobody swaps (scene → blur → scene: 0 `replaceTrack`, 0 `srcObject`). Remember a receiver's failures per (scene, remote stream id), never per offer: the look changes every ~2 s, and a device that cannot key in would retry forever with a fresh context each time.
- A receiver must never be `_active`, report through `_onOverload` (that turns the user's OWN background off and saves `off`), load the seg runtime, or see `_plate` (a remote track's empty `deviceId` matches it). Its load goes first: `onPressure` sheds the newest cut-out before the local ladder steps.
- Size the receiver from the offer (the sender's canvas), not the arriving frames: the encoder climbs through two or three sizes in a call's first 20 s, and each resize restarts the scene's accumulation. Resize only for a new shape (> 2%), never the context.
- Between two non-hosts every keyed message rides the host, and an older host drops them → `keyedRelayCapable()` fails closed. The host relays ≤ 2 non-null offers/s per source, so a sender sends ≤ 1/s (a dropped one could be its last). Keyed is mesh-only.
- **Keyed edge is harder than the composite's.** `KEY_MATTE_EDGE` (0.38–0.68) re-ramps `m` in the keyed branch only, and the receiver despills in full wherever `near < KEYIN_BAND_A0` (not weighted by `1 − a0`): a half-key pixel after 4:2:0 + VP8 reads as lime on the far side. Safe because a green subject withholds keying. The band-colour test (`unit-video-keyin`) stayed at p95 13 (no codec) / 31 (VP8); `unit-video-keyed`'s edge test applies the same second ramp.
- **The scene gets the camera's grain and vignette (`sceneFilm`, `SCENE_GRAIN`/`SCENE_VIGNETTE`), on the scene only.** It is applied where `bg` is built in both the composite and the key-in shader, never to the person (they carry their own camera's). A test that compares the output with the raw scene must set `window.__voxalSceneFilmOff = true` first. Amounts are a taste call, not measured against a real camera.
- **`sceneLight()` (LIGHT_GLSL) is the one place the scene's light lands on the person**, shared by the composite and the key-in shader: wrap that favours the outline facing the light (`uShadowOff` points TOWARD the light; outward = down the `uSoft` gradient), tint/black-level match to the scene's average (`uSceneEnv` lod 6), bounce from below, bloom above a knee. Every term is scaled by `uWrap`, so a scene or test with `wrap: 0` is untouched. `HAIR_*` is a colour-guided (joint bilateral) refinement of the matte in its band, before the keyed branch; it is NOT matting. A test that compares the keyed matte with its formula sets `window.__voxalNoHairRefine = true`. All amounts are untuned guesses.
- Tests: `canKeyIn()` refuses software GL and non-Chromium engines → opt in with `window.__voxalKeyInOnSoftwareGL` / `__voxalKeyInAnyEngine`. On software GL the production budgets refuse to key at all, so `__voxalKeyCopyBudgetMs`, `__voxalKeyInFrameBudgetMs` and `__voxalKeyInWarmWaitMs` raise them (the mesh test sets the first two). All are read at call time, so setting them after load works. Fake cameras must not be green: the effects spec's camera is `#0a0` with a moving `#0f0` dot along row 0 — the key itself, through the marker zones.

## Scene engine (Three.js on the pipeline's context; design in `docs/scene-engine.md`)

- **`renderer.resetState()` before every Three draw, and the pipeline's own state put back after** (`restoreState()` in `engine.js`). Three's cache knows nothing of the Processor's draws (stale cache = GL errors, wrong picture); and what Three leaves — `UNPACK_ALIGNMENT 4` (`resetState()` sets 4 too), `UNPACK_FLIP_Y` on after any image texture, `CULL_FACE`/`FRONT_FACE CW` after a negatively scaled mesh — breaks the odd-width mask upload, flips the camera, culls the full-screen triangle. Inside `draw()` a PMREM re-bake (an evening `envFollower`) needs `resetState()` again, not `restoreState()` (`k.environment` handles it via `drawing`).
- `compileAsync()` must see the same render target as `render()` (output colour space is in the program key; otherwise every material compiles twice). `setRenderTarget(null)` before disposing a target, or the next PMREM/render re-allocates it.
- Three's renderer makes 3 framebuffers and a few placeholder textures in its constructor and never frees them: they die with the context (the leak test allows for them; it pins *growth*).
- r186 removed `PCFSoftShadowMap` (warns, uses `PCFShadowMap` with a Vogel disk + IGN per pixel: stable under the jitter). `material.envMapIntensity` is ignored once `scene.environment` is set — use `scene.environmentIntensity`.
- A single huge ground/sea quad misdraws on SwiftShader: use a grid whose cells grow with distance.
- **Filter facade windows by the buffer's pixel, not the picture's**: picture-pixel filtering (`footprint()`) kept windows the jittered redraws disagree about — 1050 vs 556 kb/s frozen on the penthouse. `facadePatch()` defaults to the buffer.
- Thin bright lines (neon strips) alias into blocks through a half-size planar mirror: draw their floor reflections as projected geometry instead.
- A scene module that fails to load silently falls back to its old shader (by design, for users) — the scene spec checks `renderer.engine` so a broken module cannot pass the tests on the old picture.
- `scene-preview.mjs --gpu` (ANGLE Metal) gives the same pictures as SwiftShader at ~20× the speed; `--module <id>` draws a scene from its module before the catalogue says so.
- **A scene's first frame is now its JavaScript, not its shaders**: building terrain/grass/books blocks the page 40–420 ms on an M5 with a warm shader cache (countryside worst; the old shaders took 22–41 ms). Cold, the two are level (~0.5–1 s). Generate heavy geometry lazily or in chunks; never per redraw.
- **Multisample the scene's own target** (office, café): a 4–8× MSAA room halved the frozen VP9 cost (435 → 216 kb/s) — edges the jittered redraws disagreed about stop reading as motion. Turn it off on software GL (SwiftShader: +40 % per redraw).
- A test that awaited `__renderScene` after reading pipeline state must read that state first: an engine scene's `compileAsync()` yields through `setTimeout`, and the camera keeps drawing (and measuring the light) meanwhile. `ensureScene()` takes only a compiled renderer — compile with `createRenderer()` first.
- **ANGLE/Metal timer queries (`EXT_disjoint_timer_query_webgl2`) over-count a Three draw** (they include work queued before the query): time a cost with `gl.finish()` + a 1-px `readPixels` around the draw instead, and take the minimum of a short burst — a single probe after idle runs on a clocked-down GPU and reads 2–3× high.
- **A private render target sized per draw reallocates on every size change** (office/café made their own MSAA copy; the preview and the call alternate sizes): keep a small LRU of targets (the engine keeps 2) — the realloc was most of the "cost" the preview measured.
- **WebGL ignores `UNPACK_FLIP_Y` for an ImageBitmap** (Three's `tex.flipY` does nothing): decode it already flipped (`createImageBitmap(blob, {imageOrientation: 'flipY'})`) and set `flipY = false`, or a panorama sphere is upside down.
- **esbuild `--external:three` does not cover `three/examples/...` subpaths**: the GLTFLoader bundle imports Three by a relative path (`scripts/three-gltf-entry.mjs`) that the Makefile rewrites to `./three.min.js`, so the page never loads two Threes.
- A browser cannot read the screen's brightness: *Scene light* "screen" follows light/dark mode. Real brightness would need a native call per platform.
- **Chrome hidden ≠ no top inset**: with the header away the picture runs to the screen top, so `--stage-inset-top` falls back to the measured `--stage-safe-top` (`stageSafeTopPx()`), and tile flip/bg buttons + badge top corners `max()` it too — else they sit under the status bar/island, untappable. The immersive room is `position: fixed; inset: 0` rather than `100dvh`: in an iOS home-screen PWA dvh can be short of the screen (gap under the picture). Not verifiable headlessly.

## Longpipe segmentation engine (experimental; `src/longpipe-engine.js`)

- **Longpipe has no mask API** (`EffectsPipeline(MediaStream) → MediaStream`, own worker + GL; `longpipe/model` is raw ops). The mask is recovered from its output on a flat key colour: `a = (1 - e(c)) / (1 - edgeE)`, `e` = weakest channel the key has high minus strongest it has low. Voxal's whole downstream (feather, dilate, blend, scenes, light) then sees an ordinary mask. Off unless `segmentation-engine=longpipe` / `?segengine=longpipe`; MediaPipe stays default and is the automatic fallback.
- **Choose the key from the CAMERA frame's middle, never from the derived mask's subject.** A shirt the colour of the key is painted out of the mask, so measuring the mask's own subject can never see it (the first version never switched; found by the test).
- **Longpipe's stream is the unprocessed camera until its model is up, and for a few frames after `setBackground`.** Reading that as a mask calls the whole room "person". The adapter reads a mask only once the frame's four corners show the key (fails open after 1.5 s on a key change, 20 s on first load).
- **`maskCut` (0.78) is MediaPipe-specific** — it deletes the "unsure" 20-70% pixels. A matte's soft edge lives there, so the Processor sets it to 0 for Longpipe (`adoptSegmenter()`).
- Give Longpipe a `track.clone()`, not the camera track: its `destroy()` must never be able to stop the camera. `audio: 'drop'`.
- `vercel.json` sends COEP `require-corp`: Longpipe's weights from `cdn.longpipe.dev` load because that CDN answers `access-control-allow-origin: *` on a CORS fetch; it sends no `Cache-Control`, so self-host (`longpipe-weights-url`) before relying on it.
- Vendored 0.0.15 under `src/assets/longpipe/` (ESLint-ignored). npm is ahead of the GitHub repo (npm 2026-09-10, last repo commit 2026-07-17). In headless SwiftShader its stats report `modelMs 0`/`modelFps 0`: model timing is NOT measured anywhere yet — needs a real device.
- **Longpipe direct blur** (`longpipe-blur`, plain blur only): the adapter starts in key mode so the model proves it is running (its output is the UNPROCESSED camera until then — publishing that would show a sharp room), asks for `{blur:{sigma}}`, and is `live` once the corners stop matching the key; until then Voxal draws its own blur. No mask is read while live. Drawing a video texture straight to the canvas through `pDown` was upside down: the blur chain reads it back through a framebuffer that undoes the video's top-row-first storage, so `uFlip` does it explicitly (a test samples a top pixel where background and person differ). Sigma is `strength × 250`, a guess anchored on the README's sigma 20.
- Segmentation debug switches (engine, longpipe blur/preset/dilate, mask cut, diagnostic) live in Settings → Advanced, rendered by `VideoEffects.renderDebugOptions()` in both documents; the preferences window only stores, the main window applies from `storage` (`applyDebug`). URL parameters still win for a visit.
- **Longpipe on a phone reads the camera TRACK itself and ignores its turn**: an iPhone's track says 1280x720 while the pictures are portrait, and the output came out turned a quarter and stretched to landscape proportions. On phones (UA, or `longpipe-relay=1`) it is fed Voxal's own `<video>` redrawn on a canvas instead (`openRelay()`, rAF + `currentTime` check — not rVFC, see the Chromium crash above), sized from the picture, and reopened when the picture changes orientation. Fixed from a screenshot; not yet re-checked on the device.
